Generated by the `improve` skill on 2026-06-17 (planned at commit `c8d8a22`).
Goal: take the "ValuCast is fully independent of Diamond Dynasties (DD)" claim from
*mostly true by architecture* to *boringly enforceable*. Each plan is

## Audit result (steps 1-2: find + classify)

DD dependencies in the public snapshot, cards, methodology copy, and pipeline,
classified per the requested taxonomy:

- **SCORE-INPUT — none.** The score path is already clean: `_score_components`
  never reads the DD row, DD is in `PROHIBITED_SCORE_INPUTS`, and the prospect
  input contract is ValuCast-owned. "Remove score dependency" is effectively done.
- **DISPLAY-FALLBACK** — `mlb_stat_line` (DD-only, empty for prospects, no owned
  source yet — `rank_v1.py:1179`) and the transitional `stat_line_translated`
  DD fallback (owned translation is primary; DD only when a prospect has zero
  owned MiLB rows — `rank_v1.py:1136`). Both already counted in
  `validation.dd_factual_fallback`.
- **COMPARISON-ONLY** — `source_ranks` (CFR/HKB/Pipeline) in a collapsed, labeled
  external-board panel (no owned equivalent; kept per product decision). The
  outbound DD 7x7 adapter is an export, not a dependency — no action.
- **DEAD-LEGACY** — unused `dd_*` rank/value keys embedded in the public snapshot
  context (no template renders them); a `value_history` sparkline render path
  wired to a DD-only field the snapshot never populates (renders nothing);
  `scripts/sync_dd_prospect_inputs.py` (off the live workflow).
- **DEPLOY COUPLING** — `VALUCAST_REQUIRE_DD` boot guard, `/health/ready` `"dd"`
  gate, freshness DD_FEED row, and the `_select_dynasty_store`/`_select_buy_source`
  fallback that silently reverts the live board to raw DD when the snapshot is
  un-ready.
- **VALIDATOR GAP** — `source_policy.dd_values_used`/`dd_ranks_used` are hardcoded
  literals; validation only checks the literal equals `False`, never derives it
  from real row sources. `factual_path_fully_valucast_owned` is reported but never
  enforced. A score silently reverting to DD passes every gate green today.

## Product decisions (Alex, 2026-06-17)

1. **Remove DD as a live valuation fallback.** Serve the last-good ValuCast
   snapshot (stale-but-valid, labeled) or an explicit unavailable state — never
   silently serve DD values. DD stays comparison-only/benchmark/internal. Deploy
   gates validate ValuCast snapshot health directly. → Plan 002.
2. **Keep the external-board context panel, comparison-only.** Collapsed by
   default, labeled "not used in ValuCast score", under display-only fields, never
   on share graphics, and validator-enforced to never influence any ValuCast
   number. → enforcement in Plan 001, label in Plan 003.
